## Exact PowerShell commands

For the runtime already provisioned on this machine:

```powershell
Set-Location C:\Users\admin\Desktop\NEXOS-codex
node apps/api/scripts/windows-local.mjs start
node apps/api/scripts/windows-local.mjs status
node --env-file=.env apps/api/dist/main.js
```

The final command runs the API in the foreground. An API is already running on 4000 after this handoff; do not start a second instance on that port. Its PID is recorded locally in `.local/windows-runtime/api.pid`. Development watch mode is alternatively `pnpm.cmd dev:api`.

To stop only the helper-owned PostgreSQL/Redis instances while retaining data:

```powershell
node apps/api/scripts/windows-local.mjs stop
```

On a fresh Windows checkout with PostgreSQL 18 binaries installed, `node apps/api/scripts/windows-local.mjs setup` downloads and verifies the approximately 14 MB Redis archive, initializes an isolated password-protected cluster, creates missing local databases, and creates environment files only when absent. `NEXOS_PG_BIN` can override the PostgreSQL bin directory. No Windows service, firewall exception, Docker installation, global environment change, migration or seed is performed by this helper. Repeated setup/start preserves data. An existing unrelated `.env` or incomplete pre-config cluster causes setup to stop for inspection.

For a **new empty helper-created database only**, inspect and then initialize it:

```powershell
pnpm.cmd db:generate
pnpm.cmd db:status
pnpm.cmd db:migrate
node --env-file=.env --import tsx apps/api/scripts/seed-empty-local.mjs
```

These initialization operations are already complete for the current development database. The catalog initializer refuses a populated database and requires the isolated host/port/name; do not rerun ordinary seeds against user databases. Windows may lock Prisma's DLL while API/test processes are running: stop this worktree's API before client generation or a workspace build, then restart it. Do not stop unrelated Node processes.

If Prisma attempts to refetch engines unnecessarily, point to the installed Windows binaries in the command's shell:

The three checked-in migrations were reviewed and applied to the two newly created databases only. Both are up to date. No schema/migration source changed and no reset, drop, destructive migration or reseed of an existing user database occurred.
